# Шаблоны и журнал тренировок

Подготовь схему и запусти сервер из корня проекта.

```sh
npm run db:migrate -w @fitness-app/server
npm run dev:server
```

Команда подготовки схемы создаёт таблицы `users` и `exercises`, если их ещё нет. Затем она создаёт пять таблиц модуля тренировок. Маршруты ниже используют существующий Bearer access-токен и ID пользователя из токена. Вход и выдача токенов относятся к модулю авторизации.

## Шаблоны

| Метод и путь | Действие |
| --- | --- |
| `GET /workout-templates?page=0&size=20` | Список своих шаблонов с пагинацией. |
| `POST /workout-templates` | Создать шаблон, передав имя и упражнения. |
| `GET /workout-templates/:id` | Получить шаблон с упорядоченным списком упражнений. |
| `PATCH /workout-templates/:id` | Обновить имя или заменить состав. |
| `DELETE /workout-templates/:id` | Удалить шаблон. Название и состав начатых тренировок сохраняются. |

Пример тела запроса для создания шаблона.

```json
{
  "name": "День ног",
  "exercises": [
    { "exerciseId": "205c2075-2a42-4f88-b5b2-fcd09933b699", "plannedSets": 3 }
  ]
}
```

Передавай ID упражнения из личного банка. Порядок массива станет порядком упражнений. Если опустить `plannedSets`, подходы можно будет добавлять вручную. Шаблон вмещает от 1 до 100 позиций и до 100 плановых подходов на позицию. Упражнение можно удалить из банка после того, как оно убрано из шаблонов.

## Тренировки

| Метод и путь | Действие |
| --- | --- |
| `POST /workouts` | Начать тренировку по шаблону. Тело запроса содержит `templateId`. |
| `GET /workouts/active` | Получить текущую тренировку или `null`. |
| `GET /workouts?page=0&size=20` | Получить историю завершённых тренировок. |
| `GET /workouts/:id` | Получить тренировку с упражнениями и подходами. |
| `POST /workouts/:id/finish` | Завершить тренировку. Ожидающие подходы станут пропущенными. |
| `POST /workouts/:id/exercises/:exerciseId/skip` | Пропустить упражнение и его ожидающие подходы. |
| `POST /workouts/:id/exercises/:exerciseId/sets` | Добавить ожидающий подход. |
| `PATCH /workouts/:id/exercises/:exerciseId/sets/:setId` | Записать результат или пропустить подход. |

На путях тренировок `:exerciseId` берётся из `workout.exercises[].id`. Поле `workout.exercises[].exerciseId` содержит ID упражнения из банка.

У пользователя может быть одна активная тренировка. Повторный старт из того же шаблона возвращает её с кодом `200`. Старт из другого шаблона во время тренировки возвращает `409`. Даты начала и окончания служат метками в журнале.

Для завершённого подхода передай `{"status":"completed","parameterValues":{"weight_kg":20,"reps":16}}`. Для пропуска достаточно `{"status":"skipped"}`. Значения проверяются по копии `parameterSchema` из тренировки. Схема использует поля `key`, `type`, необязательные `required`, `min` и `max`. Поддерживаются `number`, `integer`, `text` (также `string`) и `boolean`. Поля по умолчанию обязательны, а оценка `wellbeing_score` по умолчанию необязательна.
