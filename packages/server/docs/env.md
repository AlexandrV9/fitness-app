# Переменные окружения сервера

Сервер читает `packages/server/.env` при запуске через `npm run dev:server` или `npm run start:server` из корня проекта. Если файла ещё нет, создай его из примера.

```sh
cp -n packages/server/.env.example packages/server/.env
```

Значения в примере подходят для локального PostgreSQL с базой `fitness-app` на стандартном порту. Пароли и секреты храни в `.env`, который исключён из Git.

## Сервер и веб-клиент

| Параметр | За что отвечает | Как выбрать значение |
| --- | --- | --- |
| `SERVER_PORT` | Порт, на котором Hono принимает HTTP-запросы. | Оставь `8000` или укажи другой свободный порт. |
| `CLIENT_PORT` | Порт клиента в конфигурации сервера. По умолчанию `3000`. | Бери порт из вывода Vite. Сейчас Vite запускается с `--port 3000` в скрипте клиента и не читает эту переменную. |
| `CLIENT_URL` | Адрес, по которому пользователь открывает веб-клиент. Хранится в конфигурации сервера. | Локально `http://localhost:3000`. Для развёрнутого приложения укажи его адрес. |
| `ALLOWED_ORIGINS` | Список источников для будущей настройки CORS. Сейчас CORS в Hono ещё не подключён. | Обычно достаточно `http://localhost:3000`. Несколько адресов разделяй запятыми без пробелов. Указывай схему, хост и порт без пути и завершающего слеша. `localhost` и `127.0.0.1` считаются разными источниками. |
| `NODE_ENV` | Значение `development` включает флаг `config.app.isDev`. Сейчас код запуска этот флаг не использует. | Задай `development` для локальной разработки или `production` для развёрнутого окружения, когда понадобится различать режимы. |

## PostgreSQL

| Параметр | За что отвечает | Как получить значение |
| --- | --- | --- |
| `DB_HOST` | Хост PostgreSQL. По умолчанию `127.0.0.1`. | Для локальной базы оставь `127.0.0.1`. Для другой базы возьми хост из её настроек подключения. |
| `DB_PORT` | TCP-порт PostgreSQL. По умолчанию `5432`. | Проверь порт через `SHOW port;` в `psql`. Если клиент подключается через проброшенный порт Docker, укажи порт на хосте. |
| `DB_NAME` | Имя базы, к которой подключается приложение. По умолчанию `fitness-app`. | Список баз показывает команда `psql -l`. Если нужной базы ещё нет, создай её командой `createdb -h 127.0.0.1 -- fitness-app` от роли с правом создания баз. |
| `DB_USER` | Роль PostgreSQL для входа. | Используй роль, под которой можешь подключиться к базе. Команда ниже показывает текущую роль. При отсутствии `DB_USER` драйвер может взять `PGUSER`, а затем системного пользователя. |
| `DB_PASSWORD` | Пароль роли из `DB_USER`, если его требует способ аутентификации. | Используй пароль, заданный для роли. Если нужно установить или заменить пароль, выполни `\password` в `psql` под нужной ролью. Для локальной базы, которая принимает подключение без пароля, оставь переменную незаданной. |

Проверь, к какой базе и под какой ролью подключается `psql`. Если используешь отдельную роль, добавь `-U имя_роли`.

```sh
psql -X -h 127.0.0.1 -p 5432 -d fitness-app \
  -c 'SELECT current_database(), current_user, inet_server_addr(), inet_server_port();'
```

[Параметры подключения node-postgres](https://node-postgres.com/features/connecting) · [Команды psql](https://www.postgresql.org/docs/14/app-psql.html)

## Секреты для токенов

Эти параметры уже читаются конфигурацией. Авторизация и сброс пароля пока не подключены, поэтому для запуска сервера с базой их можно оставить закомментированными.

| Параметр | За что отвечает |
| --- | --- |
| `ACCESS_TOKEN_SECRET` | Секрет для подписи и проверки access-токена, с которым клиент обращается к API. |
| `REFRESH_TOKEN_SECRET` | Секрет для подписи и проверки refresh-токена, если он будет выпущен как JWT. Для случайного refresh-токена, чей хеш хранится в `refresh_sessions`, этот секрет не нужен. |
| `RESET_PASSWORD_TOKEN_SECRET` | Отдельный секрет для подписи и проверки токенов сброса пароля. |

Для каждого используемого секрета запусти команду отдельно и скопируй результат в соответствующую переменную. Один запуск выдаёт 32 случайных байта в виде 64 шестнадцатеричных символов. [Документация Node.js по `randomBytes`](https://nodejs.org/api/crypto.html#cryptorandombytessize-callback)

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```
